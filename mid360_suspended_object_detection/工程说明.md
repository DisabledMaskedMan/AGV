## 3. 编译方式

### 3.1 RK3576：ROS 2 Release 构建

要求 C++17 编译器、CMake、Boost 1.75+ 的 System/JSON、yaml-cpp，以及 ROS 2 Jazzy。ROS 构建还需要已构建的 `livox_ros_driver2`、`rclcpp`、`std_msgs`、`geometry_msgs`、`visualization_msgs` 和 `rosidl_default_generators`。

```bash
sudo apt update
sudo apt install build-essential cmake libboost-system-dev libboost-json-dev libyaml-cpp-dev

cd /home/neardi/ws_livox
source /opt/ros/jazzy/setup.bash
# 加载工作空间已有的 livox_ros_driver2 等依赖

  --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DPython3_EXECUTABLE=/usr/bin/python3

```

新工作空间需先准备并构建 `livox_ros_driver2`，再加载其安装环境；不要在没有安装环境时直接执行上述第二个 `source`。指定 `/usr/bin/python3` 可避免 Conda 的 Python 与系统 ROS 消息生成环境混用。

该构建同时生成 `scan_web_server`、`suspended_object_node`、自定义消息及 C++ 测试程序。

| 项目 | 默认值/含义 |

| 无线 WebSocket | `ws://192.168.20.199:6060`，Python 默认值 |

| 初始二维 ROI | X `[0.3, 5.0]`、Y `[-1.0, 1.0]`，板端已保存值可能不同 |

`laserOffset` 仅展示，不参与车体外参变换；二维源没有采集时间戳。

框内拖动移动 ROI，四角及四边中点控制柄缩放，框外拖动平移画布，滚轮缩放视野。拖动支持负坐标，最小宽深为 0.05 m；松手只在内存生效。“应用并保存”校验并保存当前表单全部参数，重启后保留。

保存目标固定为启动时加载的 YAML。服务解析符号链接，在真实目标同目录写临时文件并原子替换，成功才切换内存配置；保留其他 YAML 字段的值，注释和排版可能改变。保存失败保持已确认配置。使用 ROS `--symlink-install` 时，默认配置通常指向源码目录；普通安装则可能写入安装目录副本。板端保存不会自动同步回电脑或 GitHub。

二维参数为 XY 边界、`cluster_distance`、聚类最少/最多点数、宽深最小/最大值及 `cloud_timeout`；三维另使用 Z 边界和高度阈值。

### 4.2 ROS 输出与网页显示

二维默认话题：`/mid360_suspended_object_detection/largest_obstacle`。

消息类型：`mid360_suspended_object_detection/msg/LargestObstacle`，目标频率 10 Hz。订阅示例：

```bash
source /opt/ros/jazzy/setup.bash
source /home/neardi/ws_livox/install/setup.bash
ros2 topic echo /mid360_suspended_object_detection/largest_obstacle
ros2 topic hz /mid360_suspended_object_detection/largest_obstacle
ros2 interface show mid360_suspended_object_detection/msg/LargestObstacle
```

| 字段 | 含义 |
| --- | --- |
| `header` | 本次发布时间及雷达 frame，时间不代表源采集时间 |
| `data_valid`、`detected` | 分析有效性及是否检出候选 |
| `status`、`error` | 等待、分析、正常、超时或异常原因 |
| `candidate_count`、`point_count` | 筛选后候选数、最大候选点数 |
| `center`、`distance_x`、`distance_y` | 包围盒中心；有符号 XY 距离分别等于 `center.x/y`，单位 m |
| `center_distance` | `sqrt(distance_x² + distance_y²)`，单位 m |
| `nearest_point`、`distance` | 最大候选中最近实际扫描点及到雷达的距离，单位 m |
| `width`、`depth`、`area` | Y 方向宽度、X 方向深度（m），宽×深面积（m²） |
| `receive_age_s`、`result_age_s` | 接收和分析结果年龄（s），不可用时为 `-1` |

例如中心在前方 2 m、右侧 0.5 m，`distance_x=2.0`、`distance_y=-0.5`。正常无候选时 `data_valid=true, detected=false`；等待、分析中或异常时 `data_valid=false, detected=false`。两者都会清零障碍物字段。

网页将选中的最大障碍物画为红框，其他候选为黄框；红框最后绘制，表格同步标记。ROS 面板展示最近成功发布的消息、实际解析/remap 后话题名、累计次数及完整 JSON。

“后端实际发布频率”根据最近 5 秒成功返回的 `publish()` 事件计算：`(事件数−1)/(末次时间−首次时间)`。少于两条显示“—”，超过 1 秒无成功发布为 0 Hz；异常时显示错误并保留最近成功消息。它不代表订阅者接收频率，后者可用 `ros2 topic hz` 观察。当前分析红框和最近发布消息可能因 100 ms 发布周期短暂不同。

三维入口输出 `/mid360_suspended_object_detection/detected`（`std_msgs/msg/Bool`）和 `/mid360_suspended_object_detection/markers`（`visualization_msgs/msg/MarkerArray`），可在 RViz 查看三维候选框。

网页接口为 `GET /api/state`、`GET /api/config`、`POST /api/config`（内存应用）和 `POST /api/config/save`（应用并保存）；状态包含当前 `largest_obstacle` 与独立的 `ros_publication` 缓存。

## 5. 使用算法及其原理

### 5.1 距离过滤与极坐标投影

二维 `scan[i]` 距离以毫米传输，先转换为 `rᵢ = scan[i] × 0.001` 米。丢弃零值、负值、非有限值及量程外值，校验角度、量程和扫描数组。角度单位弧度：

```text
θᵢ = angle_start + i × increment
xᵢ = rᵢ × cos(θᵢ)
yᵢ = rᵢ × sin(θᵢ)
```

C++ 缓存同一角度布局的正余弦，避免每次重复计算。三维入口直接使用消息中的 XYZ，过滤非有限点和全零点，并校验 frame 和点数。

### 5.2 ROI 过滤

二维保留满足 `min_x ≤ x ≤ max_x` 且 `min_y ≤ y ≤ max_y` 的点。三维还要求 `min_z ≤ z ≤ max_z`。ROI 先限制参与计算的范围，但也会截断跨越边界的物体，因此包围盒反映的是区域内观测到的部分。

### 5.3 空间哈希网格与并查集欧氏聚类

将每个点视为图的顶点，两点欧氏距离不超过 `cluster_distance=d` 时连边，每个连通分量为一个簇。簇可通过中间点形成链式连接，不要求簇内任意两点距离都小于 d。

为避免无条件两两比较，以 d 为网格边长，用 `floor(x/d)`、`floor(y/d)`（三维增加 `floor(z/d)`）构造哈希网格。距离不超过 d 的点必定位于本格或相邻格，因此二维只搜索 3×3 共 9 格，三维搜索 3×3×3 共 27 格。

对邻域点计算平方距离：二维比较 `Δx²+Δy² ≤ d²`，三维增加 `Δz²`。满足条件时用并查集合并所属集合；路径压缩和按秩合并减少重复查找。最终按集合根节点汇总簇。

网格减少稀疏场景的邻点比较，但不会下采样；单格点过密时仍可能产生大量比较，不能保证所有输入都为线性复杂度。

### 5.4 轴对齐包围盒与筛选

每个簇分别统计坐标最小/最大值，得到轴对齐包围盒（AABB），不估计物体朝向：

```text
深度 depth = max_x − min_x
宽度 width = max_y − min_y
三维高度 height = max_z − min_z
中心 cx = (min_x + max_x) / 2
中心 cy = (min_y + max_y) / 2
二维面积 area = width × depth
```

先按簇点数范围，再按宽深范围过滤；三维额外检查高度范围。二维同时保存簇内距离雷达最近的实际点。包围盒中心是几何边界中心，不是点集质心；最近点距离也不等于中心距离。

### 5.5 最大障碍物选择

仅在通过筛选的二维候选中选择。依次比较：面积更大优先；面积相同选最近实际点距离更小者；再按中心 X、Y 从小到大排序；仍相同则按边界坐标和点数确定稳定顺序。

C++ 的 Web 红框与 ROS 发布使用同一结构化选择结果，Python 基线采用相同选择规则。三维入口发布所有通过筛选的候选，不使用这个二维“最大障碍物”话题。

## 6. 能力边界与运行机制

二维数据只有平面距离，没有 Z，不能测量离地高度或判断是否悬挂；二维消息 Z=0 只是占位。三维节点通过 Z/高度区域筛选产生悬挂物几何候选，但没有语义分类、地面拟合或姿态补偿，仍需标定雷达安装位置和 ROI。

二维接收线程持续读取持久 WebSocket，仅保留最新扫描；检测最多 10 Hz。同一内容和配置不重复分析，在线配置改变会立即清除旧结果并触发重新分析。C++ 缓存投影布局及分析 JSON，HTTP 与 ROS 共用线程安全结果，不重复聚类。

后续扫描分析期间可短暂沿用未过期的上次完成结果；结果配置已失效、目标扫描接收超时、源 `timeoutSec` 异常或连接断开时，清除候选。连接失败按 1、2、5 秒退避，持续失败后每 5 秒重试。相同扫描持续到达会刷新接收时间，不单独判为失效；由于缺少源采集时间戳，不能据此证明上游采集持续更新。

ROS executor 每 100 ms 独立发布一次，使用 Reliable、KeepLast(1)、Volatile QoS，即使扫描内容不变也继续发布有效性状态。三维节点则按输入消息处理，并由 200 ms 定时器检查超时。

网页的正常未检出、无数据和异常状态分开展示；网页与服务断开时清空实时框及发布内容。ROI 点数为零可能只是检测区域没有覆盖当前有效点，可先点“全部点”观察。

自动测试与合成回放通过不等于现场障碍物验收完成。现场应放置已知物体核对位置、尺寸和候选框，再移走物体确认结果消失。
