# MID360 点云避障工程说明

## 1. 启动方式

### 1.1 RK3576 启动 Web 点云与 ROI 编辑

在板卡终端执行（工程已经编译安装）：

```bash
source /opt/ros/jazzy/setup.bash
source /home/neardi/ws_livox/install/setup.bash

ros2 launch mid360_obstacle_avoidance mid360_obstacle.launch.py \
  enable_web_editor:=true \
  enable_roi_editor:=false \
  params_file:=/home/neardi/ws_livox/src/mid360_obstacle_avoidance/config/obstacle.yaml \
  lidar_config:=/home/neardi/ws_livox/src/mid360_obstacle_avoidance/config/MID360_board.json
```

此命令同时启动 Livox 驱动、C++ 检测节点和 Python Web 服务，不启动 RViz 窗口。专用雷达配置使用 `Mid360s`，雷达地址为 `192.168.1.143`，接收主机地址为 `192.168.1.5`；这些值要求与现场网络一致。

在 VS Code Remote-SSH 的“端口”面板转发板卡 **8080**，打开面板提供的本地地址；若映射的本地端口也是 8080，可访问 `http://127.0.0.1:8080`。服务默认只监听板卡 `127.0.0.1`，不需要板卡显示器。Three.js 资源随包提供，无需 CDN 或板卡 Node.js。

### 1.2 开始、停止检测与查看输出

当前配置 `detection_enabled_on_start: false`，启动后默认暂停检测。打开另一个已加载 ROS 环境的板卡终端：

```bash
source /opt/ros/jazzy/setup.bash
source /home/neardi/ws_livox/install/setup.bash

# 开始检测
ros2 topic pub --once /mid360_obstacle_avoidance/enable_detection \
  std_msgs/msg/Bool '{data: true}'

# 停止检测；本节点不再请求停车
ros2 topic pub --once /mid360_obstacle_avoidance/enable_detection \
  std_msgs/msg/Bool '{data: false}'

# 查看完整状态或独立停车输出（分别运行）
ros2 topic echo /mid360_obstacle_avoidance/status
ros2 topic echo /mid360_obstacle_avoidance/stop_required
```

启停状态持续到下一条指令或节点重启，不设置指令超时；重复相同指令不重置检测。网页显示实际启停和停车状态，不提供启停按钮。

### 1.3 无界面运行与复用已有驱动

无界面运行仍显式使用板卡专用配置：

```bash
ros2 launch mid360_obstacle_avoidance mid360_obstacle.launch.py \
  enable_web_editor:=false enable_roi_editor:=false \
  params_file:=/home/neardi/ws_livox/src/mid360_obstacle_avoidance/config/obstacle.yaml \
  lidar_config:=/home/neardi/ws_livox/src/mid360_obstacle_avoidance/config/MID360_board.json
```

若 Livox 驱动已经运行，在上述相应命令末尾追加 `start_driver:=false`，避免重复启动驱动。已有驱动须输出 `livox_ros_driver2/msg/CustomMsg`（`xfer_format=1`）；默认输入 `/livox/lidar`，坐标系 `livox_frame`，可用 `input_topic:=... frame_id:=...` 指定。坐标系参数仅设置名称，不做坐标变换。

需要本地图形桌面时可设置 `enable_roi_editor:=true` 启动 RViz2。结束程序使用启动终端的 `Ctrl+C`。

## 4. 使用算法及原理

处理流程：**Livox 点云 → 消息校验 → 有效点过滤 → ROI 筛选 → 空间聚类 → 每群尺寸/点数过滤 → 障碍状态与停车请求**。

### 4.1 输入校验与 ROI

检查输入坐标系是否为期望名称、点数组是否非空，以及 `point_num` 是否等于数组长度。逐点丢弃含 NaN/Inf 的坐标和 `(0,0,0)` 点。

ROI 为输入坐标系下的轴对齐长方体，要求 X 向前、Y 向左、Z 向上，坐标单位为米。六个边界均包含等号，只有 ROI 内有效点参与聚类。ROI 外点既不统计，也不能连接 ROI 内的两个群；编辑模式仍显示 ROI 外的有效点，便于标定。

每轴长度至少 `0.01 m`，X 最小边界不小于 0。不执行 TF 变换、地面分割或姿态补偿，需通过标定排除地面和车体。

### 4.2 空间哈希网格与 BFS 连通聚类

设相邻距离阈值为 `d = cluster_distance_threshold`，以边长 `d` 构建三维哈希网格。点 `(x,y,z)` 的格坐标为：

```text
(floor(x/d), floor(y/d), floor(z/d))
```

距离不超过 `d` 的两点只能位于本格或周围 26 格，因此搜索这 27 格，再以三维欧氏距离 `sqrt(dx²+dy²+dz²) <= d` 确认相邻，减少不必要的全局两两比较。

使用广度优先搜索（BFS）扩展相邻点，形成连通点群。邻接允许传递：A 邻近 B、B 邻近 C，即使 A 与 C 距离超过阈值，也属于同群。结果不依赖输入点顺序，不把多个独立小群的点数相加后判定。

### 4.3 点数、对角线与可选体积过滤

对每个群统计点数 `N` 和轴对齐包围盒跨度 `ΔX、ΔY、ΔZ`。同时满足以下条件才接受为障碍物：

```text
N >= min_obstacle_points
sqrt(ΔX² + ΔY² + ΔZ²) >= min_cluster_diagonal
min_cluster_volume == 0 或 ΔX × ΔY × ΔZ >= min_cluster_volume
```

任意一个群合格即可判定存在障碍物，整个 ROI 都是检测停车范围；没有额外 `stop_distance`。采用单帧判定，不增加跨帧确认等待。

| 参数（中文含义） | 当前随包 YAML 值 | 单位/约束 |
| --- | --- | --- |
| `roi_min_x / roi_max_x`（X 边界） | 约 `[0.103722, 1.671695]` | m |
| `roi_min_y / roi_max_y`（Y 边界） | 约 `[-0.993971, 0.284687]` | m |
| `roi_min_z / roi_max_z`（Z 边界） | 约 `[-0.066421, 0.5]` | m |
| `cluster_distance_threshold`（相邻点最大距离） | `0.1` | m，有限且 > 0，兼容 ROI 网格范围 |
| `min_obstacle_points`（每群最少点数） | `10` | 整数，1～4294967295 |
| `min_cluster_diagonal`（最小点群对角线） | `0.1` | m，有限且 ≥ 0 |
| `min_cluster_volume`（最小包围盒体积） | `0.0` | m³，有限且 ≥ 0；0 关闭 |
| `cloud_timeout`（有效点云超时） | `0.5` | s，有限且 > 0 |

表中 ROI 为方便阅读的近似值，完整标定值以当前 YAML 为准；运行时编辑后应以 `detector_config` 为准。包围盒体积不是物体实际体积，默认关闭，避免过滤墙面、薄板等目标。

该方法可过滤分散噪点和小点群，但密集噪声仍可能通过；相邻阈值过大会串接噪点，过小会拆散稀疏目标。单帧判定不含时间滤波，参数需结合实际噪声及最小目标标定。

### 4.4 输出含义

`/mid360_obstacle_avoidance/status` 的类型为 `mid360_obstacle_avoidance/msg/ObstacleStatus`：

| 字段 | 含义 |
| --- | --- |
| `header` | 最近收到的输入帧 Header，心跳不会伪造新的点云时间戳 |
| `data_valid` | 输入健康状态；只有有限非零点且消息校验通过才有效，ROI 内无点不等于输入无效 |
| `obstacle_detected` | 检测开启且至少一个 ROI 点群通过过滤 |
| `stop_required` | 本节点是否请求停车，规则见第 5 节 |
| `nearest_distance` | 所有合格群的最小 X，单位 m；不是欧氏距离或车头净空；有效帧无合格群为 `+inf`，暂停/无效/待重新判定为 `NaN` |
| `obstacle_points` | 所有合格群点数总和 |
| `stop_zone_points` | 兼容字段，与 `obstacle_points` 相同 |

独立 Bool 话题 `stop_required` 和 `detection_enabled` 分别输出停车请求与实际启停状态。节点只提供检测信息，不直接发送底盘速度或制动指令。

## 5. 停车规则与在线调参

### 5.1 停车及超时规则

```cpp
stop_required = detection_enabled && (obstacle_detected || cloud_timed_out);
```

暂停期间始终不请求停车，但继续校验输入、发送心跳、显示点云并支持 ROI 编辑。刚开启或配置修改后清除旧障碍结果，等待新帧；等待本身不停车，已有超时仍停车。

开启时以单调时钟开始新的有效点云等待窗口；随后以最近有效点云的接收时刻计时。100 ms 定时器检查超时并发布状态心跳，超时响应受该检查周期和实际调度影响。空帧、全无效点、数量不匹配或坐标系错误不刷新有效时间，因此持续异常最终会超时停车。

重复 true、修改 ROI 或算法参数不延后超时；修改 `cloud_timeout` 后，按已有接收间隔和新阈值重新判断。有效点云恢复后，有合格障碍群继续停车，无合格群解除停车。下游控制器还需监测状态心跳是否中断。

### 5.2 Web 编辑、保存与只读参数

网页显示完整有效点云、ROI 和六个轴向控制柄。拖动或输入 ROI 边界立即修改内存，下一帧使用新范围，不自动保存。

- **保存 ROI 到 YAML**：仅将当前六边界写入启动时指定的 `params_file`。
- **恢复启动值**：恢复本次启动 ROI，不恢复算法参数，不自动保存。
- **应用并保存参数**：整组校验五个算法候选值，与操作执行时的实际六边界一起保存十一项；保存成功才一次性应用新算法参数。失败时算法保持原值，已拖动 ROI 保持当前状态。

保存由 C++ 服务执行，保留其他参数、注释、权限和换行格式；使用同目录临时文件原子替换并检查并发修改。缺键、重复键或文件不可写等情况会拒绝保存。

ROS 参数保持启动时只读，`ros2 param get` 返回启动值。网页和 RViz 操作的是节点的可变内存配置，当前实际值及版本通过 `roi_state`、`detector_config` 发布；算法提交使用 `apply_detector_config` 服务，因此无需动态改写 ROS 参数。网页调参无需编译或重启，保存后重启可重新加载。

话题面板显示完整状态、独立 Bool、配置、PointCloud2/ROI Marker 摘要及接收时间、年龄，区分未收到、断线和消息过期。话题名、坐标系、Web/RViz 开关及启动检测开关仍是启动配置。
